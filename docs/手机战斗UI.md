# 手机战斗 UI

## 启用规则

战斗场景中的 `MobileBattleLayout` 组件会在同时满足以下条件时启用手机专属布局：

1. 运行平台带有 Godot 的 `mobile` 特性，或平台名称为 Android/iOS。
2. 当前可用画布为竖屏，即高度大于宽度。

`project.godot` 中的 `display/window/handheld/orientation` 固定为 `1`（Portrait），并通过 `.mobile` 特性覆盖将手机基准视口设为 `720×1280`；这是竖屏方向不会自动交换基准宽高时所必需的配置。桌面端仍使用原有 `1280×720` 横屏 UI。Android 导出预设启用了 `screen/edge_to_edge`，背景会延伸到完整物理屏幕；布局组件再将可点击控件限制在 `DisplayServer.get_display_safe_area()` 返回的安全区域内。开发时可在布局组件的 `force_mobile_ui` 中设为 `true`，在编辑器或桌面环境预览手机布局。

## 竖屏布局规则

| 区域 | 布局 |
| --- | --- |
| 上方战斗区 | 占可用高度的 52%，显示双方角色、HUD、当前回合与轮次。 |
| 角色站位 | 我方位于战斗区左下，敌方位于右上。 |
| HUD | 敌方 HUD 位于左上，我方 HUD 位于右下。 |
| 下方操作区 | 显示 2×2 技能按钮；主动换人或技能选目标时显示 3 列×2 行角色格。 |
| 最底操作栏 | 从左到右固定为：角色、战斗、普攻、逃跑、记录。 |
| 记录按钮 | 首次点击以战斗记录替换上方战斗区，按钮文字变为“战斗”；再次点击恢复实时战斗区。底部操作区始终可用。 |

## 响应式数值

以下数值定义于 `scripts/ui/mobile_battle_layout.gd`，均可在场景检查器中调整：

- 战斗区高度比例：`0.52`，可调范围 `0.42–0.68`。
- 屏幕内边距比例：`0.032`，可调范围 `0.015–0.08`，最小值 `12` 逻辑像素。
- 控件间距比例：`0.022`，可调范围 `0.01–0.06`，最小值 `8` 逻辑像素。
- 底部操作栏高度比例：`0.078`，可调范围 `0.055–0.13`，最小高度 `56` 逻辑像素。
- 角色卡牌缩放基数：`0.85 × 屏幕宽度 / 1280`，最终限制在 `0.48–0.90`。
- HUD 缩放：`屏幕宽度 / 1280`，最终限制在 `0.70–1.15`。
- 技能标题字号：屏幕宽度的 `4.0%`，限制在 `24–42`。
- 技能说明字号：屏幕宽度的 `3.2%`，限制在 `19–34`。

该方案以比例而非固定分辨率计算，适合 OnePlus Ace 5 一类高纵横比、窄边框的现代 Android 手机。背景采用覆盖缩放填满整块屏幕，状态栏、前摄打孔和手势导航区由系统安全区域约束交互按钮，避免全屏显示时控件被遮挡。

## 主菜单手机布局

主菜单的 `MobileMainMenuLayout` 使用相同的移动端识别与安全区域映射规则：

- 背景使用覆盖缩放延伸到完整屏幕。
- 队伍模式与随机模式按钮改为纵向堆叠，固定在安全区域下半部。
- 按钮横向边距为安全区域宽度的 `7%`（最小 `20`），间距为高度的 `2.5%`（最小 `16`）。
- 单个按钮高度为安全区域高度的 `10%`，最终限制在 `76–148` 逻辑像素。
- 菜单文字字号为安全区域宽度的 `5.2%`，最终限制在 `28–44`。

## 模块职责

- `MobileBattleLayout`：检测移动端、重排 UI、处理记录视图和窗口尺寸变化。
- `fighting.gd`：继续负责回合、技能、角色切换与胜负；仅在布局变更时同步实际角色 Sprite，并在记录模式隐藏角色动画。
- `fighting.tscn`：提供移动端操作区背景、分隔线、布局组件和记录按钮信号。
- `MobileMainMenuLayout`：重排主菜单背景、队伍模式和随机模式入口，使两个按钮位于手机安全区域的下半部。

修改移动端比例、按钮顺序或 HUD 位置时，应同步更新本文档；不要把回合或伤害规则写入布局组件。
